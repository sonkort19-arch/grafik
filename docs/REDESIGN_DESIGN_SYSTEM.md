# MA График — дизайн-система редизайна

Статус: утверждённая спецификация для этапов 3–9.

Цель: максимально близко повторить выбранный пользователем визуальный стиль MA График / MA CRM, сохранив существующую бизнес-логику, данные и критические сценарии.

## 1. Визуальное направление

Интерфейс должен выглядеть как единая современная бизнес-система: светлый фон, белые рабочие поверхности, строгая синяя акцентная палитра, небольшие радиусы, тонкие границы, очень мягкие тени, высокая плотность информации на desktop и упрощённая структура на mobile.

Не использовать декоративные градиенты, неон, стеклянные карточки, тяжёлые тени, лишнюю анимацию и маркетинговые декоративные блоки внутри рабочего приложения.

Основной синий используется для действий и навигации. Зелёный, янтарный и красный — только для смысловых статусов.

```css
  --ma-bg: #F6F7F9;
  --ma-surface: #FFFFFF;
  --ma-surface-soft: #F8FAFC;
  --ma-text: #18202B;
  --ma-text-secondary: #667085;
  --ma-text-tertiary: #98A2B3;
  --ma-border: #E3E7ED;
  --ma-border-strong: #D0D5DD;

  --ma-primary: #246BFD;
  --ma-primary-hover: #1D5DEB;
  --ma-primary-soft: #EEF4FF;
  --ma-primary-soft-strong: #E2ECFF;

  --ma-success: #21A66B;
  --ma-success-soft: #EAF8F1;
  --ma-warning: #CC8915;
  --ma-warning-soft: #FFF5E5;
  --ma-danger: #CF4E4E;
  --ma-danger-soft: #FDEEEE;
  --ma-purple: #7A53C8;

  --ma-radius-control: 10px;
  --ma-radius-card: 14px;
  --ma-radius-large: 18px;

  --ma-shadow-card: 0 1px 2px rgba(16, 24, 40, .04), 0 4px 14px rgba(16, 24, 40, .04);

```

Эти значения являются целевыми. На этапах внедрения допускается минимальная локальная корректировка, если она нужна для существующего контента или safe-area, но не создание новой параллельной палитры.

## 3. Типографика

Не добавлять новую внешнюю font-зависимость только ради редизайна. Использовать стабильный системный стек:

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Arial, sans-serif;
```

Целевые размеры:
- Заголовок страницы desktop: 26–30px / 700–800.
- Заголовок страницы mobile: 22–24px / 750–800.
- Заголовок большой карточки: 18–20px / 700.
- Заголовок обычной карточки: 15–17px / 700.
- Основной текст: 14–15px / 400–600.
- Вторичный текст: 12–13px / 400–600.
- Подписи таблиц: 12–13px / 600.
- Значение KPI: 26–32px / 750–800.

Не использовать рабочий текст меньше 12px. На iPhone input/select/textarea — минимум 16px, чтобы Safari не увеличивал экран при фокусе.

## 4. Сетка и отступы

Базовый шаг: 4px. Основные отступы: 8 / 12 / 16 / 20 / 24 / 32px.

Desktop:
- sidebar: 244px;
- topbar: 64px;
- основной контент: максимум 1440px;
- отступ рабочей области: 24–32px;
- расстояние между основными секциями: 20–24px;
- карточки в сетке: gap 16px.

Mobile:
- горизонтальный отступ страницы: 16px;
- расстояние между секциями: 16px;
- внутренний отступ карточки: 14–16px;
- учитывать `env(safe-area-inset-top)` и `env(safe-area-inset-bottom)`.

## 5. Карточки

Обычная карточка:
- белый фон;
- граница 1px `--ma-border`;
- радиус 14px;
- тень только `--ma-shadow-card`;
- padding 16px mobile / 18–20px desktop.

Крупная карточка/панель:
- радиус 18px;
- padding 20–24px desktop;
- без декоративной тяжёлой тени.

Карточки KPI:
- desktop: по возможности 4 в ряд;
- tablet: 2 в ряд;
- mobile: 2×2, при очень узком экране — 1 колонка;
- главное число визуально доминирует, подпись и изменение вторичны.

## 6. Кнопки и поля

Primary:
- фон `--ma-primary`;
- белый текст;
- border-radius 10px;
- desktop высота 40–42px;
- mobile высота 44–48px;
- без градиента.

Secondary:
- белый фон;
- граница `--ma-border`;
- текст `--ma-text` или `--ma-primary` для навигационного действия.

Danger:
- красный используется только для опасного действия;
- обычная отмена не должна быть красной.

Поля:
- высота 42px desktop, 44–48px mobile;
- border-radius 10px;
- граница `--ma-border`;
- focus: синяя рамка/outline, без резкого свечения.

## 7. Статусы

Зелёный = успешно / открыто / выполнено.
Янтарный = внимание / задержка / риск.
Красный = ошибка / нарушение / критическая проблема.
Серый = нейтрально / закрыто / неактивно.
Синий = выбранное, навигация, основное действие, информационный акцент.

Цвет точки сервиса не должен спорить со статусами. Если сервисы различаются цветом, использовать дополнительный маркер/подпись, а не превращать весь статус в зелёный или красный.

## 8. Desktop shell — целевая структура

Слева постоянный sidebar, сверху компактный topbar, справа рабочая область.

Sidebar:
- логотип/название `MA График` сверху;
- активный пункт — мягкий синий фон `--ma-primary-soft` + синий текст/иконка;
- неактивные пункты — тёмно-серый текст;
- иконки простые outline, одного визуального семейства;
- настройки и профиль владельца — в нижней части.

Целевая навигация только по реально существующей функциональности:
1. Сегодня
2. График
3. Календарь
4. CRM — переход в существующий `crm.html`
5. KPI сотрудников
6. История смен
7. Кошельки
8. Отчёт владельца
9. Настройки

Не создавать фиктивные разделы ради сходства с макетом. Новые пункты появляются только вместе с реальной функцией.

Topbar:
- высота около 64px;
- слева контекст текущего раздела;
- справа только полезные элементы: состояние сохранения/облака, уведомление при необходимости, вход/профиль;
- элементы конкретного модуля остаются внутри рабочей области, если они не нужны глобально.

## 9. Mobile shell — целевая структура

Нижняя навигация — 5 пунктов:
1. Сегодня
2. График
3. CRM
4. Кошельки
5. Ещё

`Ещё` содержит:
- Календарь
- KPI сотрудников
- История
- Отчёт владельца
- Настройки

На mobile не переносить весь desktop sidebar в скрытую боковую панель: нижняя навигация остаётся главным способом перемещения.

Высота нижней панели — 64px + safe-area. Активный пункт — синий. Иконка и подпись должны быть читаемыми без лишнего декора.

## 10. Responsive breakpoints

- `>= 1180px`: полный desktop layout, sidebar 244px.
- `760–1179px`: compact desktop/tablet, sidebar допускается 216–228px или компактный режим при нехватке места.
- `< 760px`: mobile layout, sidebar скрыт, нижняя навигация включена.
- `< 390px`: особо узкий mobile — сокращать gap и padding, но не уменьшать кликабельные элементы ниже 44px.

Breakpoints вводить централизованно. Не плодить отдельные почти одинаковые media-query для одного и того же поведения.

## 11. Таблицы и списки

Desktop:
- таблицы плоские, с тонкими разделителями;
- header светло-серый;
- row hover очень мягкий;
- не использовать тяжёлые рамки вокруг каждой ячейки.

Mobile:
- критические таблицы должны переходить в карточки/списки;
- горизонтальный скролл допускается только когда карточное представление делает данные менее понятными;
- основные действия доступны без прокрутки вправо.

## 12. Модальные окна и sheets

Desktop:
- modal по центру;
- максимальная ширина зависит от задачи;
- радиус 18–20px;
- `--ma-shadow-modal`;
- затемнение фона спокойное.

Mobile:
- предпочтительно bottom sheet для коротких действий;
- крупные формы могут занимать почти весь экран;
- учитывать safe-area и экранную клавиатуру;
- кнопка закрытия минимум 40×40px.

## 13. Иконки

Не использовать случайный набор emoji как постоянную навигацию.

Целевой стиль:
- простые outline-иконки;
- stroke около 1.8–2px;
- одинаковая визуальная масса;
- desktop 18–20px, mobile 20–22px.

Если новая библиотека иконок создаёт зависимость/риск, использовать локальные SVG или текущие средства проекта. Не подключать тяжёлую библиотеку только ради нескольких значков.

## 14. Анимации

Только функциональные переходы:
- hover/focus: 120–160ms;
- открытие sheet/modal: 160–220ms;
- без bounce, параллакса и постоянных декоративных анимаций.

Уважать `prefers-reduced-motion`.

## 15. Экран владельца «Сегодня» — визуальная цель для этапа 4

Экран должен читаться владельцем за 5–10 секунд.

Приоритет сверху вниз:
1. Требует внимания.
2. Состояние двух точек/смен.
3. Ключевые показатели дня, если реальные данные доступны.
4. Быстрые действия: KPI, отчёт владельца, замена.
5. Дополнительные детали ниже.

Не показывать выдуманную выручку, количество заказов или рейтинг ради сходства с макетом. Только реальные данные приложения.

## 16. Экран менеджера «Открыть смену» — визуальная цель для этапа 5

Этот экран должен быть максимально простым:
- MA График / Рабочая смена;
- точка;
- дата;
- менеджер/мастер;
- текущий статус;
- одно главное действие `Открыть смену` или `Закрыть смену`;
- PIN/подтверждение только там, где это требует существующая логика.

Не добавлять лишнее меню и бизнес-аналитику на рабочий экран смены.

## 17. CRM — визуальная цель для этапа 7

CRM должна выглядеть частью той же системы, а не отдельным приложением.

Сохраняется существующая структура:
- Обзор
- Заказы
- Клиенты
- Продажи
- Склад
- Финансы
- Отчёты

Цвета, радиусы, кнопки, typography, topbar и mobile-nav приводятся к тем же tokens.

Порядок CRM-скриптов и bootstrap не менять ради дизайна.

## 18. Доступность и touch

- кликабельная область mobile: минимум 44×44px;
- focus-visible должен быть заметен;
- текст и фон должны сохранять нормальный контраст;
- цвет не должен быть единственным способом показать статус;
- disabled-состояние должно быть визуально понятным, но текст остаётся читаемым.

## 19. Что запрещено во время внедрения этой дизайн-системы

- менять расчёт графика ради верстки;
- менять структуру Supabase;
- менять финансовую математику;
- менять ключи localStorage;
- переименовывать рабочие DOM id без проверки всех обращений;
- менять порядок script-тегов без отдельной причины;
- добавлять фиктивные данные из референсного макета;
- подключать новую тяжёлую UI-библиотеку;
- одновременно редизайнить все модули одним коммитом;
- удалять старый CSS до финального этапа 9.

## 20. Порядок внедрения

Эта спецификация внедряется только по этапам из `docs/REDESIGN_RULES.md`.

Этап 3 создаёт shell и базовые tokens.
Этап 4 меняет только «Сегодня».
Этап 5 меняет рабочий экран смены.
Этап 6 переносит основные модули.
Этап 7 приводит CRM к системе.
Этап 8 переносит остальные разделы.
Этап 9 выполняет финальную пиксельную доводку и только после успешных проверок удаляет устаревшие стили.

## Критерий визуального успеха

Цель — не копировать маркетинговую картинку буквально, а воспроизвести её рабочий визуальный язык примерно на 90–95%: структура, плотность, светлый фон, белые поверхности, синий акцент, компактный sidebar, спокойные карточки, понятные KPI и единый mobile shell.

При конфликте между визуальным сходством и стабильностью приоритет: данные → логика → стабильность → совместимость → удобство → дизайн.
